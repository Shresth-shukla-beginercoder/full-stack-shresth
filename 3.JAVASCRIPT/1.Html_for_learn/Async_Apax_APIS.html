1. The Call Stack

  • The call stack is where JavaScript keeps track of what function is currently running.
  • It works LIFO — Last In, First Out. The last function pushed on is the first one popped off.
  • Every time a function is called, a new "frame" is pushed. When it returns, that frame is popped.
  • JavaScript is single-threaded — it has exactly one call stack, so it can only do one thing at a time.
  • If the stack never empties (infinite recursion), you get a "Maximum call stack size exceeded" error.

Example

function multiply(a, b) {
  return a * b;
}
function square(n) {
  return multiply(n, n);   // multiply() pushed
}
function printSquare(n) {
  const result = square(n); // square() pushed
  console.log(result);
}
printSquare(5); // printSquare -> square -> multiply, then unwind

Practice Question

Write three functions a(), b(), and c() where a calls b, and b calls c. Each should console.log its own name when it starts. Call a() and predict the order of logs.

The stack is LIFO, but the logs happen on the way IN (when each function starts), so the order you see is simply a, then b, then c — the order they were called, not the order they return.

2. Web APIs

  • The JS engine itself (V8, SpiderMonkey, etc.) only understands the language — it has no idea what setTimeout, fetch, or the DOM are.
  • Those features are given to JS by the browser (or Node.js) — they are called Web APIs.
  • Common Web APIs: setTimeout/setInterval, the DOM, fetch, geolocation, localStorage.
  • When you call setTimeout(fn, 1000), JS hands the timer off to the browser and keeps running — the browser calls fn back later. This is what makes async behavior possible in a single-threaded language.

Example

console.log("1: start");
setTimeout(() => {
  console.log("2: this runs later (handled by the browser's timer API)");
}, 1000);
console.log("3: end (runs before the timeout, even though it's written after)");

Practice Question

Use console.log to print "A", then use setTimeout to print "B" after 500ms, then print "C" immediately after the setTimeout call. What order do they appear in?

setTimeout hands the callback to the Web API — your synchronous code (A, then C) always finishes first, no matter how small the delay is.

3. Single-Threaded JS & The Event Loop

  • JS has ONE call stack → it can run only one line of code at a time (single-threaded).
  • Async work (timers, network requests) is delegated to Web APIs, which run outside the JS engine.
  • When that work finishes, its callback doesn't jump straight onto the call stack — it waits in the callback queue (task queue).
  • The event loop constantly checks: "Is the call stack empty?" If yes, it takes the next item from the queue and pushes it onto the stack.
  • This is why setTimeout(fn, 0) still runs after all synchronous code — the stack has to be empty first.

Example

console.log("1");
setTimeout(() => console.log("2 (from queue)"), 0);
console.log("3");
// Output order: 1, 3, 2 — even with a 0ms delay!

Practice Question

Log "start", then schedule "middle" with setTimeout(..., 0), then log "end". Before running, write down the order you expect, then run it to check.

Correct order: start, end, middle — synchronous code always finishes before the event loop pulls anything from the queue.

4. Demo: Fake Request Using Callbacks

  • Before promises existed, async results were handled with callback functions — a function passed into another function, to be run once the work is done.
  • A "fake request" simulates a network call using setTimeout so we can practice async patterns without a real server.
  • Problem: chaining several dependent callbacks leads to deeply nested code — nicknamed "callback hell".

Example

function fakeRequest(url, callback) {
  console.log("Requesting:", url);
  setTimeout(() => {
    const data = { url, status: 200, body: "Some fake data" };
    callback(data);
  }, 1000);
}
fakeRequest("/movies/123", (data) => {
  console.log("Got data:", data);
});

Callback Hell Example

fakeRequest("/user", (user) => {
  fakeRequest("/user/" + user.id + "/orders", (orders) => {
    fakeRequest("/orders/" + orders[0] + "/items", (items) => {
      console.log("Finally got items:", items); // 3 levels deep!
    });
  });
});

Practice Question

Using the fakeRequest(url, callback) function (already loaded on this page), request "/products", and inside its callback, log the data you receive with a friendly message like "Products:".

fakeRequest("/products", (data) => { console.log("Products:", data); });

5. Demo: Fake Request Using Promises

  • The same fake request, but returning a Promise instead of taking a callback.
  • Now we call .then() to react when it resolves, instead of passing a callback in.
  • Chaining .then() calls reads top-to-bottom instead of nesting deeper and deeper — this is the first big win of promises.

Example

function fakeRequestPromise(url) {
  console.log("Requesting:", url);
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      const data = { url, status: 200, body: "Some fake data" };
      resolve(data);
    }, 1000);
  });
}
fakeRequestPromise("/movies/123")
  .then((data) => console.log("Got data:", data));

Chaining Instead of Nesting

fakeRequestPromise("/user")
  .then((user) => fakeRequestPromise("/user/" + user.url + "/orders"))
  .then((orders) => fakeRequestPromise("/orders/" + orders.url + "/items"))
  .then((items) => console.log("Finally got items:", items));

Practice Question

Using fakeRequestPromise(url) (already loaded), request "/products" and chain a .then() that logs the result.

fakeRequestPromise("/products").then((data) => console.log(data));

6. The Magic of Promises

  • A Promise is an object representing a value that isn't ready yet, but will be — either successfully (fulfilled) or not (rejected).
  • Three states: pending → fulfilled or pending → rejected. Once settled, a promise never changes state again.
  • .then(onSuccess, onError) handles the fulfilled case (and optionally the rejected case).
  • .catch(onError) handles rejection — cleaner than passing a second argument to .then.
  • .finally() runs regardless of success or failure — great for cleanup like hiding a loading spinner.
  • Promise.all([p1, p2]) waits for every promise to resolve (or fails fast if any reject).

Example: then / catch / finally

fakeRequestPromise("/good-url")
  .then((data) => console.log("Success:", data))
  .catch((err) => console.log("Error:", err))
  .finally(() => console.log("Request finished (always runs)"));

Example: Promise.all

Promise.all([
  fakeRequestPromise("/a"),
  fakeRequestPromise("/b"),
  fakeRequestPromise("/c")
]).then((results) => console.log("All done:", results));

Practice Question

Call fakeRequestPromise("/bad-url") (this URL is rigged to reject in the demo — see hint), and handle both success with .then and failure with .catch.

fakeRequestPromise("/bad-url").then(data => console.log(data)).catch(err => console.log("caught:", err));

7. Creating Your Own Promises

  • Build a promise with new Promise((resolve, reject) => { ... }).
  • The function you pass in (the executor) runs immediately — call resolve(value) when things succeed, or reject(reason) when they fail.
  • Useful for wrapping ANY async operation — timers, file reads, even wrapping old callback-style APIs so they can be used with .then().

Example: a coin-flip promise

function flipCoin() {
  return new Promise((resolve, reject) => {
    const result = Math.random() < 0.5 ? "heads" : "tails";
    setTimeout(() => {
      if (result === "heads") resolve("You got heads! 🪙");
      else reject("You got tails — try again.");
    }, 800);
  });
}
flipCoin()
  .then((msg) => console.log(msg))
  .catch((msg) => console.log(msg));

Practice Question

Use Math.floor(Math.random() * 6) + 1 to get 1–6, then resolve(n) if n >= 4 else reject("too low: " + n).

8. The async Keyword

  • Putting async in front of a function makes it always return a Promise — automatically, even if you just return a plain value.
  • If the function returns a normal value, the promise resolves with that value. If it throws, the promise rejects.
  • async functions are still called and used with .then()/.catch() like any promise — but their real power comes from pairing with await (next topic).

Example

async function greet() {
  return "Hello!"; // automatically wrapped in a Promise
}
greet().then((msg) => console.log(msg)); // "Hello!"

async function willThrow() {
  throw "Oops!"; // automatically becomes a rejected Promise
}
willThrow().catch((err) => console.log("Caught:", err));

Practice Question

9. The await Keyword

  • await can only be used inside an async function.
  • It pauses the async function at that line until the promise settles, then "unwraps" the resolved value — no more .then() chains needed.
  • Code after await reads like normal, synchronous, top-to-bottom code — even though it's async under the hood.
  • Important: await only pauses the current async function — the rest of the program keeps running (JS is still single-threaded and non-blocking).

Example: rewriting the promise chain with await

async function getOrderItems() {
  const user = await fakeRequestPromise("/user");
  const orders = await fakeRequestPromise("/user/" + user.url + "/orders");
  const items = await fakeRequestPromise("/orders/" + orders.url + "/items");
  console.log("Finally got items:", items);
}
getOrderItems();

Practice Question

const data = await fakeRequestPromise("/products"); console.log("Loaded:", data);

10. Handling Errors in Async Functions

  • Wrap await calls in a normal try...catch block — this is the standard way to handle promise rejections inside async functions.
  • If an awaited promise rejects, control jumps straight to the catch block, just like a thrown error.
  • You can also add a finally block for cleanup code that must run either way.

Example

async function safeLoad(url) {
  try {
    const data = await fakeRequestPromise(url);
    console.log("Success:", data);
  } catch (err) {
    console.log("Something went wrong:", err);
  } finally {
    console.log("Done trying, either way.");
  }
}
safeLoad("/bad-url"); // this URL is rigged to reject in the demo

11. Intro to AJAX

  • AJAX = Asynchronous JavaScript And XML — a technique, not a specific tool or language.
  • It means: use JavaScript to talk to a server in the background, without reloading the whole page.
  • Despite the name, modern AJAX almost always uses JSON, not XML.
  • Tools that do AJAX in JS: the old XMLHttpRequest, the modern fetch(), and libraries like Axios (all covered later).
  • Classic example: a search box that shows suggestions as you type, without the page refreshing.

Conceptual Example

// Without AJAX: clicking a link reloads the ENTIRE page
// With AJAX: JS quietly fetches new data and updates just one part of the DOM

button.addEventListener("click", async () => {
  const res = await fetch("/api/latest-news");
  const data = await res.json();
  newsDiv.innerHTML = data.headline; // only this part of the page changes
});

12. Intro to APIs

  • API = Application Programming Interface — a set of rules that lets one program talk to another.
  • A web API is usually a server that responds to HTTP requests with data (often JSON), at specific URLs called endpoints.
  • Example: https://api.tvmaze.com/search/shows?q=girls is an endpoint that returns TV show data as JSON.
  • APIs let you build on top of huge datasets (weather, movies, maps) without owning that data yourself.
  • Most public APIs are documented — the docs tell you the available endpoints, required parameters, and response format.

Live Example: a real public API

fetch("https://api.tvmaze.com/search/shows?q=girls")
  .then((res) => res.json())
  .then((data) => console.log(data[0].show.name));

13. What is JSON

  • JSON = JavaScript Object Notation — a lightweight, text-based format for exchanging data.
  • It looks like a JS object/array, but it's plain text, and it's stricter: keys must be in double quotes, no trailing commas, no functions or undefined.
  • Almost every API sends/receives JSON, because nearly every language can parse it.
  • JSON.stringify(obj) — turns a JS object into a JSON string (to send data).
  • JSON.parse(str) — turns a JSON string back into a JS object (to use data you received).

Example

const user = { name: "Shresth", course: "Engineering", active: true };

const jsonString = JSON.stringify(user);
console.log(jsonString); // '{"name":"Shresth","course":"Engineering","active":true}'
console.log(typeof jsonString); // "string"

const parsedBack = JSON.parse(jsonString);
console.log(parsedBack.name); // "Shresth" — back to a real object

14. HTTP Verbs (Methods)

HTTP verbs tell the server what kind of action you want to perform on a resource:

VerbPurposeExample
GETRead/retrieve data (no changes)Get a list of products
POSTCreate new dataSubmit a signup form
PUTReplace an entire resourceUpdate a whole user profile
PATCHPartially update a resourceChange just a user's email
DELETERemove a resourceDelete a comment

Together with URLs, these verbs form RESTful API design — same URL, different verb, different action.

Example: same endpoint, different verbs

fetch("/api/products/12");                          // GET  — read product 12
fetch("/api/products", { method: "POST", body: ... }); // POST — create a product
fetch("/api/products/12", { method: "PUT", body: ... });   // PUT  — replace it
fetch("/api/products/12", { method: "PATCH", body: ... }); // PATCH — edit one field
fetch("/api/products/12", { method: "DELETE" });     // DELETE — remove it

15. HTTP Status Codes

Every HTTP response includes a 3-digit status code telling you how it went:

RangeMeaningCommon Examples
1xxInformational100 Continue
2xxSuccess200 OK, 201 Created, 204 No Content
3xxRedirection301 Moved Permanently, 304 Not Modified
4xxClient error (you made a mistake)400 Bad Request, 401 Unauthorized, 404 Not Found
5xxServer error (server's fault)500 Internal Server Error, 503 Service Unavailable

Example: checking status with fetch

fetch("https://api.tvmaze.com/shows/1")
  .then((res) => {
    console.log("Status code:", res.status);
    console.log("Was it ok?", res.ok); // true for 200-299
    return res.json();
  })
  .then((data) => console.log("Show name:", data.name));

Practice Question

A missing show returns status 404, so res.ok will be false — fetch does NOT reject on 404, you have to check res.ok yourself!

16. Using Postman

  • Postman is a free desktop/web app for testing APIs — without writing any code.
  • You pick a verb (GET/POST/etc.), type a URL, optionally add headers/body, hit Send, and see the response instantly.
  • Why developers use it: to explore an API before writing JS for it, to debug a request that's failing, and to test POST/PUT bodies without building a form first.
  • Typical workflow: New Request → choose GET → paste URL → Send → inspect the JSON response and status code in the response panel.
  • For POST requests: switch to the "Body" tab, choose "raw" + "JSON", and type the JSON object you want to send.

What a Postman request maps to in code

// Postman: GET https://api.tvmaze.com/search/shows?q=girls
// ...is equivalent to this fetch call:
fetch("https://api.tvmaze.com/search/shows?q=girls")
  .then(res => res.json())
  .then(data => console.log(data));

// Postman: POST https://example.com/api/users, Body(raw JSON): {"name":"Sam"}
// ...is equivalent to:
fetch("https://example.com/api/users", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ name: "Sam" })
});

Practice Question

As a comment, describe the exact steps you'd take in Postman to test a POST request to /api/comments sending {"text": "hi"}.

Set method to POST, paste the URL, go to Body tab, choose raw + JSON, type the object, click Send, then check the status code and response body.

17. Understanding Query Strings

  • A query string is the part of a URL after ? — used to send extra parameters to the server.
  • Format: key=value pairs, joined by &. Example: ?q=girls&page=2.
  • Common uses: search terms, pagination, filters, sorting.
  • In JS, URLSearchParams makes building/reading them easy, instead of hand-concatenating strings.

Example

const params = new URLSearchParams({ q: "the office", page: "1" });
console.log(params.toString()); // "q=the+office&page=1"

const url = "https://api.tvmaze.com/search/shows?" + params.toString();
console.log(url);

// Reading params from an existing URL:
const parsed = new URLSearchParams("?q=girls&page=2");
console.log(parsed.get("q"));    // "girls"
console.log(parsed.get("page")); // "2"

Practice Question

const params = new URLSearchParams({ category: "shoes", sort: "price", inStock: "true" }); console.log(params.toString());

18. HTTP Headers

  • Headers are metadata sent along with every HTTP request and response — extra information that isn't part of the main body.
  • Common request headers: Content-Type (what format the body is in), Authorization (auth tokens), Accept (what format you want back).
  • Common response headers: Content-Type, Content-Length, Cache-Control.
  • In fetch, you set request headers with the headers option; you can read response headers via res.headers.get(...).

Example

fetch("https://api.tvmaze.com/shows/1", {
  headers: { "Accept": "application/json" }
}).then((res) => {
  console.log("Content-Type header:", res.headers.get("content-type"));
  return res.json();
}).then((data) => console.log("Show:", data.name));

Practice Question

fetch(url, { headers: { Accept: "application/json" } }).then(res => console.log(res.headers.get("content-type")));

19. XHR & The Fetch API

  • XMLHttpRequest (XHR) is the original, older way to make HTTP requests in JS — callback-based and verbose.
  • fetch() is the modern replacement — promise-based, cleaner, built into every modern browser.
  • fetch(url) resolves with a Response object — you usually then call .json() (also a promise!) to get the actual data.
  • Two awaits are typical: one for the response, one for parsing its body.

XHR (old way)

const xhr = new XMLHttpRequest();
xhr.open("GET", "https://api.tvmaze.com/shows/1");
xhr.onload = () => console.log(JSON.parse(xhr.responseText).name);
xhr.onerror = () => console.log("Request failed");
xhr.send();

fetch (modern way)

async function loadShow() {
  const res = await fetch("https://api.tvmaze.com/shows/1");
  const data = await res.json();
  console.log(data.name);
}
loadShow();

Practice Question

Write an async function that fetches https://api.tvmaze.com/shows/3 and logs the show's summary field (it'll contain HTML tags — that's fine).

const res = await fetch(url); const data = await res.json(); console.log(data.summary);

20. Introducing Axios

  • Axios is a popular third-party library for making HTTP requests — an alternative to fetch.
  • Key differences from fetch: Axios automatically parses JSON (no manual .json() call), and it rejects the promise automatically on 4xx/5xx status codes.
  • Load it via CDN: <script src="https://cdn.jsdelivr.net/npm/axios/dist/axios.min.js"></script> (already loaded on this page).
  • The actual data is on response.data (fetch calls it "the body", axios calls it "data").

Example: fetch vs axios, side by side

// fetch — two awaits needed
const res = await fetch(url);
const data = await res.json();

// axios — one await, JSON parsed automatically
const response = await axios.get(url);
console.log(response.data);

Practice Question

Use axios.get() to fetch https://api.tvmaze.com/shows/4 and log response.data.name.

const response = await axios.get(url); console.log(response.data.name);

21. Setting Headers with Axios

  • Pass a config object as the last argument to any axios method, with a headers key.
  • Same idea for query params — axios has a dedicated params option that auto-builds the query string for you.
  • You can also set default headers for EVERY request axios makes, via axios.defaults.headers.common.

Example

axios.get("https://api.tvmaze.com/search/shows", {
  params: { q: "girls" },              // becomes ?q=girls automatically
  headers: { "Accept": "application/json" }
}).then((response) => {
  console.log("First result:", response.data[0].show.name);
});

axios.get(url, { params: { q: "office" }, headers: { Accept: "application/json" } }).then(r => console.log(r.data.length));

22. Mini Project: TV Show Search App

  • Puts everything together: a form, preventDefault, axios, query params, JSON data, and updating the DOM with results.
  • Uses the free TVmaze API — no API key required.
  • Try searching for a show below — this is a fully working live demo, not just a code sample.

Live App

The Code Behind It

const form = document.querySelector("#tvSearchForm");
const input = document.querySelector("#tvSearchInput");
const resultsDiv = document.querySelector("#tvResults");

form.addEventListener("submit", async (e) => {
  e.preventDefault(); // stop the page from reloading
  const query = input.value;
  const response = await axios.get("https://api.tvmaze.com/search/shows", {
    params: { q: query }
  });
  resultsDiv.innerHTML = response.data.map((result) => `
    <div class="tv-card">
      <img src="${result.show.image ? result.show.image.medium : ""}">
      <h4>${result.show.name}</h4>
    </div>
  `).join("");
});
