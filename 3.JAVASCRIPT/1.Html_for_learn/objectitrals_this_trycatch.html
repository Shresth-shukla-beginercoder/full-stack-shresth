1 · Introducing object literals

What is an object literal?

An object literal is a comma-separated set of key: value pairs wrapped in { }. It's the simplest way to group related data and behavior together, without needing a class or constructor.

// A plain object literal
const student = {
  name: "Shresth",
  age: 20,
  branch: "CSE"
};
console.log(typeof student); // "object"
Keys are always strings (or Symbols) under the hood; values can be anything — numbers, strings, arrays, functions, even other objects.
2 · Creating object literals

Ways to create one

// 1. Directly with key:value pairs
const car = { brand: "Tata", model: "Nexon", year: 2024 };

// 2. Shorthand property names (when variable name = key name)
const brand = "Tata", year = 2024;
const car2 = { brand, year };          // same as { brand: brand, year: year }

// 3. Computed property names
const field = "color";
const car3 = { [field]: "red" };       // { color: "red" }

// 4. Empty object, filled later
const empty = {};
empty.city = "Gorakhpur";
3 · Accessing data out of an object

Dot vs bracket notation

const car = { brand: "Tata", model: "Nexon", "fuel type": "petrol" };

console.log(car.brand);            // "Tata"        (dot notation)
console.log(car["model"]);         // "Nexon"       (bracket notation)
console.log(car["fuel type"]);     // needed when key has a space

// Dynamic key access
const key = "brand";
console.log(car[key]);             // "Tata"

// Accessing a missing property
console.log(car.color);            // undefined (no error)
Use dot notation when the key is a valid identifier. Use bracket notation when the key has spaces, is dynamic, or comes from a variable.
4 · Modifying an object

Add, update, delete

const car = { brand: "Tata", year: 2024 };

car.year = 2025;          // update existing property
car.color = "white";      // add a new property
delete car.color;         // remove a property

// Freezing (prevents any further changes)
Object.freeze(car);
car.year = 2099;          // silently fails (or throws in strict mode)
console.log(car.year);    // still 2025
5 · Nesting arrays and objects

Objects inside objects, arrays inside objects

const student = {
  name: "Shresth",
  marks: [88, 92, 79],              // array nested in object
  address: {                         // object nested in object
    city: "Gorakhpur",
    state: "UP"
  },
  friends: [
    { name: "Aman", age: 20 },       // array of objects
    { name: "Riya", age: 21 }
  ]
};

console.log(student.address.city);   // "Gorakhpur"
console.log(student.marks[1]);       // 92
console.log(student.friends[0].name);// "Aman"
Chain . and [] together to dig deeper into nested structures — read it left to right, one level at a time.
6 · The for loop

Syntax & examples

// for (initialization; condition; increment)
for (let i = 0; i < 5; i++) {
  console.log("Iteration:", i);
}

// Counting down
for (let i = 10; i > 0; i--) {
  console.log(i);
}

// Skipping by 2
for (let i = 0; i < 10; i += 2) {
  console.log(i); // 0,2,4,6,8
}
7 · Looping over arrays

for, forEach, and for...of on arrays

const fruits = ["apple", "banana", "mango"];

// classic for loop (index-based)
for (let i = 0; i < fruits.length; i++) {
  console.log(i, fruits[i]);
}

// .forEach — array method, no index management needed
fruits.forEach((fruit, index) => {
  console.log(index, fruit);
});

// for...of — cleanest for values only
for (const fruit of fruits) {
  console.log(fruit);
}
8 · Nested loops

A loop inside a loop

// Multiplication table 1-3
for (let i = 1; i <= 3; i++) {
  for (let j = 1; j <= 3; j++) {
    console.log(`${i} x ${j} = ${i * j}`);
  }
}

// Looping a 2D array (matrix)
const grid = [[1, 2], [3, 4], [5, 6]];
for (let row = 0; row < grid.length; row++) {
  for (let col = 0; col < grid[row].length; col++) {
    console.log(grid[row][col]);
  }
}
The outer loop runs once per row; the inner loop runs fully for every single iteration of the outer loop.
9 · while loops

while vs do...while

// while — checks condition BEFORE running
let i = 0;
while (i < 5) {
  console.log(i);
  i++;
}

// do...while — runs body ONCE, then checks condition
let j = 0;
do {
  console.log(j);
  j++;
} while (j < 5);

// do...while always runs at least once, even if condition is false:
let k = 10;
do {
  console.log("runs once:", k);
} while (k < 5);
10 · The break keyword

Exiting a loop early

for (let i = 0; i < 10; i++) {
  if (i === 5) break;   // stops the loop entirely
  console.log(i);        // prints 0,1,2,3,4
}

// continue — skips just this iteration, loop keeps going
for (let i = 0; i < 5; i++) {
  if (i === 2) continue;
  console.log(i);        // prints 0,1,3,4 (2 is skipped)
}

// break inside nested loops only exits the INNERMOST loop
outer: for (let i = 0; i < 3; i++) {
  for (let j = 0; j < 3; j++) {
    if (j === 1) break outer; // labeled break exits BOTH loops
    console.log(i, j);
  }
}
11 · The for...of loop

Iterating any "iterable"

// Works on arrays, strings, Maps, Sets — NOT plain objects
for (const char of "Hi") console.log(char);      // "H" then "i"

const nums = [10, 20, 30];
for (const n of nums) console.log(n);

// With entries() to get index + value together
for (const [index, value] of nums.entries()) {
  console.log(index, value);
}
for...of gives you the values directly — no index bookkeeping, no .length checks. It's the most readable loop for arrays and strings.
12 · Iterating over objects (for...in)

Looping through keys

const car = { brand: "Tata", model: "Nexon", year: 2024 };

// for...in gives you the KEYS of an object
for (const key in car) {
  console.log(key, "=", car[key]);
}

// Common alternatives using Object methods + for...of
for (const key of Object.keys(car)) console.log(key);
for (const value of Object.values(car)) console.log(value);
for (const [key, value] of Object.entries(car)) {
  console.log(`${key}: ${value}`);
}
Rule of thumb: use for...of for arrays/strings (values), use for...in or Object.entries() for plain objects (keys).
13 · The mysterious 'this' keyword

What does 'this' refer to?

this refers to the object that is currently "calling" the function — its value depends on how a function is invoked, not where it's written.

const car = {
  brand: "Tata",
  showBrand: function () {
    console.log(this.brand);   // 'this' = car, because car.showBrand() called it
  }
};
car.showBrand();               // "Tata"

// Losing 'this' — a common bug
const grabbed = car.showBrand;
grabbed();                     // undefined ('this' is no longer car)

// Arrow functions do NOT have their own 'this' —
// they inherit 'this' from the surrounding (enclosing) scope
const car2 = {
  brand: "Tata",
  showBrand: () => {
    console.log(this.brand);   // 'this' here is NOT car2 (arrow fn) → undefined
  }
};

// 'this' inside a regular method's callback needs care:
const car3 = {
  brand: "Tata",
  items: ["seat", "wheel"],
  list() {
    this.items.forEach((item) => {
      // arrow function here correctly keeps 'this' = car3
      console.log(this.brand, item);
    });
  }
};
car3.list();
Quick rule: regular function → this = whatever called it. Arrow function → this = inherited from where it was defined.
14 · try...catch

Handling errors gracefully

try {
  const car = { brand: "Tata" };
  console.log(car.engine.type);   // engine is undefined → error!
} catch (error) {
  console.log("Something went wrong:", error.message);
} finally {
  console.log("This always runs, error or not.");
}

// Throwing your own errors
function getAge(age) {
  try {
    if (age < 0) throw new Error("Age cannot be negative");
    return age;
  } catch (err) {
    console.log("Caught:", err.message);
    return null;
  }
}
getAge(-5);   // "Caught: Age cannot be negative"
Use try/catch around code that might fail at runtime — accessing deep/uncertain object properties, parsing JSON, network calls, user input — so one error doesn't crash the whole script.
15 · Defining methods & their uses

Functions that live inside objects

const car = {
  brand: "Tata",
  speed: 0,

  // method — full function syntax
  accelerate: function (amount) {
    this.speed += amount;
    console.log(`${this.brand} is now at ${this.speed} km/h`);
  },

  // method — ES6 shorthand (preferred, same result)
  brake(amount) {
    this.speed = Math.max(0, this.speed - amount);
  }
};

car.accelerate(40);   // "Tata is now at 40 km/h"
car.brake(10);
console.log(car.speed); // 30
Why use methods? They bundle behavior with the data it acts on — instead of a separate function taking the object as a parameter, the object "knows how" to do things to itself via this. This is the core idea behind object-oriented code.
