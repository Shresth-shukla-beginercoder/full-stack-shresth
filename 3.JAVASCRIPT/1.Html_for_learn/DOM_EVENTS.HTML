1. Introduction to DOM Events

  • Event = something that happens in the browser: a click, a key press, a page load, a form submit, a mouse move, etc.
  • JavaScript can "listen" for these events and run code in response — this is called event-driven programming.
  • Three ways to attach an event handler, from oldest to modern:
    1. Inline HTML attribute — <button onclick="...">
    2. DOM property — element.onclick = function(){}
    3. element.addEventListener('click', function(){}) — the modern, recommended way
  • Common event categories:
CategoryExamples
Mouseclick, dblclick, mouseover, mouseout, mousemove, mousedown, mouseup
Keyboardkeydown, keyup, keypress
Formsubmit, change, input, focus, blur
Window/Documentload, resize, scroll, DOMContentLoaded

2. Inline Event Handlers

      

        
    
          
  • Written directly in HTML as an attribute: <button onclick="sayHi()">
    • 
          
  • The attribute's value is treated as JS code that runs on that event.
    • 
          
  • element.setAttribute('onclick', 'code') does the exact same thing from JavaScript — it's the same mechanism under the hood.
    • 
          
  • Downsides: mixes HTML and JS (hard to maintain), can only attach one handler per event, security/CSP issues, code as a string is easy to break.
    • 
          
  • Rarely used in real projects today — shown here mainly so you recognize it and understand why we prefer addEventListener.

4. The this Keyword in Event Handlers

      

        
    
          
  • Inside a regular function passed to addEventListener, this refers to the element the listener is attached to (same as event.currentTarget).
    • 
          
  • Inside an arrow function, this is not rebound — it keeps whatever this was in the surrounding scope (often window or undefined).
    • 
          
  • Rule of thumb: use a regular function(){} when you need this to mean "the clicked element"; use an arrow function when you don't care about this.

5. The Event Object

      

        
    
          
  • Every handler automatically receives an event object (conventionally named e or event) describing what happened.
    • 
        

        

          
PropertyMeaning

          
e.typeThe event name, e.g. "click"

          
e.targetThe exact element that triggered the event

          
e.currentTargetThe element the listener is attached to

          
e.clientX / e.clientYMouse position (mouse events)

          
e.key / e.codeWhich key was pressed (keyboard events)

          
e.preventDefault()Stops the browser's default behavior

          
e.stopPropagation()Stops the event from bubbling further

6. Form Events & preventDefault()

      

        
    
          
  • The submit event fires on the <form> element (not the button) when it's submitted.
    • 
          
  • By default, submitting a form reloads the page (or navigates) — almost always NOT what you want in a JS app.
    • 
          
  • e.preventDefault() inside the submit handler stops that default reload, letting you handle the data with JS instead (validation, fetch/AJAX, etc.).
    • 
          
  • Always attach the listener to the form's submit event — not a click on the button — so it also works when the user presses Enter.
    • 
        

        
form.addEventListener('submit', function(e) {
  e.preventDefault();      // stop page reload
  const data = form.elements['username'].value;
  // ...validate / use data...
});

7. Input & Change Events

      

        

          
EventFires when…

          
inputThe value changes, on every keystroke (live, real-time)

          
changeThe value has changed AND the element loses focus (or for select/checkbox, immediately on selection)

        

        
    
          
  • Use input for live feedback: character counters, live search, live preview.
    • 
          
  • Use change for things you only care about once the user is "done": dropdowns, checkboxes, finalized text fields.

8. Event Bubbling

      

        
    
          
  • When an event fires on an element, it first runs on that element, then "bubbles up" and also runs on every ancestor's listener for the same event type.
    • 
          
  • Order: target → parent → grandparent → … → document.
    • 
          
  • e.stopPropagation() stops the bubble from going any further up.
    • 
          
  • Bubbling is why event delegation (next topic) works.
    •

9. Event Delegation

      

        
    
          
  • Event delegation: instead of adding a listener to every child, add one listener on a common parent and use e.target to figure out which child was actually clicked.
    • 
          
  • Why: fewer listeners (better performance), and it automatically works for elements added later (dynamically created), since the listener lives on the parent.
    • 
          
  • Pattern:
    • 
        

        
parent.addEventListener('click', function(e) {
  if (e.target.matches('.item')) {
    // e.target is the specific child clicked
  }
});
